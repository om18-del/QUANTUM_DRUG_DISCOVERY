# LIMITATIONS.md

What this build does **not** verify. Anything listed here is either unmeasured, unavailable, or known to be weaker than it looks; it must not be presented as a result.

## Known limitations

- **The quantum endpoints are a classical simulation, and the artifact cannot be regenerated here.** `GET /api/quantum/h2-curve` reads the stored grid; `POST /api/quantum/simulate` runs a real VQE loop (2-layer Ry ansatz, SciPy COBYLA, Qiskit estimator, seed-reproducible) graded against a NumPy diagonalisation of the same stored Pauli terms. It is still a local CPU simulation: no quantum hardware and no device-noise model. `noise` is accepted and echoed but never applied (shot-based runs do carry real sampling noise), and `within_chemical_accuracy` is deliberately `null` for shot-based runs — chemical accuracy is a noiseless claim only. A shot run's headline energy is a **fresh re-evaluation at the final optimal parameters** (not the minimum of the noisy optimisation trace) and carries its sampling uncertainty as `vqe_energy_std_ha`; the variational guard is scoped to noiseless statevector runs, so a shot run is never refused for sitting below exact on sampling noise. The 4-parameter ansatz's worst noiseless error over the whole grid is ~1e-3 Ha at the stretched 2.65–3.00 Å geometries (exact figures and command in RESULTS.md) — comfortably inside 1.6 mHa, but visibly not machine precision there. The artifact itself was generated offline with PySCF, which publishes no Windows wheel, so this build can validate it (`scripts/validate_hamiltonian_file.py`, `tests/test_h2_hamiltonian_artifact.py`) but cannot regenerate it locally.
- **Only H2 is simulated with VQE. LiH (active space) will serve only a precomputed curve and an exact reference once its artifact exists. Larger molecules are not simulated.** The curve endpoint takes `?molecule=` (`h2` default, `lih` known), and `GET /api/quantum/molecules` reports which artifacts exist. LiH's `lih_sto3g_active.json` is **not** in this repository: `available: false` and a `503` until the user generates it in Colab. The one ansatz in this build is a 2-qubit Ry+CX circuit, so a non-H2 `simulate` request is refused with `422 vqe_not_supported_for_molecule` rather than answered by an ansatz that was never written or tested, and the exact reference is refused above 8 qubits.
- **The resource estimate is counted from a formula, and its orbital counts have never been machine-checked.** `GET /api/quantum/resources?formula=` (`POST /api/quantum/resources` is kept as a body-shaped alias) reports STO-3G spatial orbitals, electrons, full and reduced qubits, statevector memory, a feasibility verdict and an optional active-space block, with every figure tagged `exact` or `estimated`. `exact` there means closed-form in code — the counts follow the minimal-basis rule (H/He 1 function, Li–Ne 5, Na–Ar 9) and the neutral atomic numbers — **not** that a basis file confirmed them: every payload carries `verified_against_pyscf: false`, and the offline `mol.nao` cross-check in `scripts/precompute_hamiltonians.ipynb` has not been run here (PySCF is not installed in this environment). **No Pauli-term count and no circuit size is reported at all**, because neither follows from a formula; the only statement about term growth is the asymptotic "roughly N^4 in the number of orbitals". **The classical simulation limits are project choices and rough estimates** — an 8-qubit interactive cap and a rough 25-qubit laptop statevector ceiling, neither a measured hardware or algorithm bound — and `simulable_in_app` means the size fits this app's budget, **not** that a simulation exists for that molecule, because H2 is the only molecule with a VQE ansatz. Spin and charge are not modelled: the electron count is the neutral count from the formula and there is no charge input.
- **RDKit tests are skipped where RDKit is blocked.** On a host where the RDKit DLL is blocked, the RDKit-dependent tests skip instead of running. A skip is not a pass, and the conformer/property paths are unverified on that host.
- **The ligand N/O donor/acceptor rule is permissive.** Hydrogen-bond contact counts come from a geometric heuristic over deposited heavy atoms (no hydrogens, no protonation states), so they are **upper bounds**, not observed hydrogen bonds. The same applies to the salt-bridge rule.
- **CI has never run on a runner.** `.github/workflows/ci.yml` exists, but no job has executed on a GitHub-hosted runner, so "tests pass in CI" is unverified.
- **Docking is not built.** There is no docking pipeline, no Vina run and no RMSD. The Drug-Target Studio reports measured contacts from deposited crystal coordinates, which need no docking.
